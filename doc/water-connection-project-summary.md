# WaterController — сводка проекта

Версия документа: 1.0 · Дата: 2026-10-20

> Контроллер главного водопровода дома: подключается к магистральному вводу воды, контролирует расход и давление, обнаруживает протечки и автоматически перекрывает воду, чтобы предотвратить серьёзный ущерб.

## 1. Структура системы

```
          +12V DC (БП)
              │
     ┌────────┼──────────────────────────────┬──────────────────────┐
     │        │                              │                      │
     │   LM2596 (MOD1) ──► 1N5817 (D2) ──► +5V                      │
     │                                       │                      │
     │      ┌────────────────────────────────┼─────────────┐        │
     │      │                                │             │        │
     │   ESP32-DevKitC-32U (U1)          ADS1115 (U4)   HV-сторона  │
     │   5V-пин → LDO → +3V3             VDD = 5V       Level       │
     │      │                                │          Shifter(U2) │
     │      │ IO21/IO22 (I2C, 3.3V) ──► U2 ──► SDA/SCL               │
     │      │ IO19/IO18 ──►|── D3/D4 ──────► IN1/IN2 ──► DRV8871 (U3)│
     │      │ SW1/SW2 (кнопки) ─► IN1/IN2    │                       │
     │      │ IO34/IO35 ◄─ R7/R8 ◄─ IN1/IN2  │                       │
     │      │ IO32/33/25/26 ─► LED1–LED4     │                       │
     │      │                                │             VM=+12V ─┘
     │      │                                │             OUT1/OUT2
     │      │                          A0 ◄── J2 ◄── SWP-300       │
     │      │                                       (питание +12V)  ▼
     │      │ IO23 ◄── U2 ◄── R13 ◄── J3 ◄── YF-B10 (+5V)    J1 ──► Кран CR01
     │      │                                                      (CWX-25S)
     │      │                                     LED5/LED6 (Open/Close) на J1
     │   Wi-Fi (внешняя антенна) ──► MQTT-брокер ──► Home Assistant
```

## 2. Оборудование

### 2.1 Микроконтроллер

| Параметр | Значение |
|---|---|
| Модуль | ESP32-WROOM-32U (разъём U.FL под внешнюю антенну) |
| Отладочная плата на схеме | ESP32-DevKitC-32U, 38 выводов (символ `_my_MC_Dev_Boards:ESP32-DEVKITC-32-38PINS`) |
| Питание | 5 В на вывод `5V` платы, 3.3 В получается встроенным LDO платы |
| Почему 5 В | 5 В — единое напряжение для периферии: ADS1115 питается от 5 В, чтобы диапазон его входа покрывал сигнал датчика давления 0–5 В |

### 2.2 Электрокран

| Параметр | Значение |
|---|---|
| Модель | CR01, 12 В, DN20 (3/4"), модель CWX-25S |
| Управление | 2 провода, направление — сменой полярности |
| Особенность | в открытом и закрытом положении ток не потребляет (сохраняет положение при пропадании питания) |
| Питание | 12 В |
| Мощность | < 2 Вт |
| Рабочий ток | < 80 мА (только во время хода) |
| Обратная связь о положении | нет (2-проводная модель) |

### 2.3 Электронный датчик давления

| Параметр | Значение |
|---|---|
| Модель | SWP-300, 0–10 бар, G1/2 |
| Подключение | 1/2" папа |
| Питание | 12–36 В DC (номинал 24 В); на схеме — **+12 В** |
| Выход | 0–5 В (линейно: 2 бар/В) |

### 2.4 Датчик расхода

| Параметр | Значение |
|---|---|
| Модель | YF-B10, 1", 2–50 л/мин |
| Питание | DC 3.5–24 В (датчик Холла, питание обязательно); на схеме — **+5V** (J3) |
| Выход | импульсы, 476 имп/л |
| Частота | при 50 л/мин ≈ 400 Гц; при 2 л/мин ≈ 16 Гц |

### 2.5 Механический манометр

Резьба 1/4" папа, ставится на тот же тройник, что и электронный датчик (визуальный контроль).

## 3. Гидравлическая схема подключения (из `Water Connection.txt`)

**Пиллер (на улице):** счётчик → обратный клапан (аль-хозер) → ручной кран → труба PEX25 до хацера.

**Хацер, версия 1 (по потоку воды):**

| # | Элемент | Резьба |
|---|---|---|
| 1 | Труба PEX25 | — |
| 2 | Переходник PEX25 → 3/4 | 3/4 мама → папа |
| 3 | Ручной кран | 3/4 мама → папа |
| 4 | **Электрокран CR01** | 3/4 мама → мама |
| 5 | Переходник 3/4 → 1" | 1" папа → папа |
| 6 | **Датчик расхода YF-B10** | 1" мама → мама |
| 7 | Переходник 1" → 3/4 | 3/4 папа → мама |
| 8 | Вассат (редуктор давления) | 3/4 папа → папа |
| 9 | Фильтр | 3/4 мама → мама |
| 10 | Ручной кран | 3/4 папа → мама |
| 11 | Тройник | 3/4 → 3/4 |
| 12 | Переходник 3/4 → PEX25 | 3/4 мама → мама |

**Отвод от тройника (п. 11):** тройник 3/4 + заглушка → переходник 3/4 → 1/2 → **электронный датчик давления** (1/2) и механический манометр (1/4).

Датчик давления стоит после редуктора и фильтра, то есть измеряет давление в домашней сети.

### 4.3.1 Входная цепь датчика давления (R1, R2, C8)

```
J2.3 (сигнал) ──┬──[R1 4.7 кОм]──┬──► A0 (U4, ADS1115)
                │                │
            [R2 100 кОм]     C8 100 нФ
                │                │
GND ────────────┴────────────────┴──► GND (U4)
```

| Цепь (нетлист) | Узлы |
|---|---|
| Net-(J2-Pin_3) | J2.3, R1.1, R2.1 |
| Net-(U4-A0) | R1.2, C8.2, U4.7 (A0) |
| GND | J2.1, R2.2, C8.1, U4.2 |

| Элемент | Назначение | Расчёт |
|---|---|---|
| R1 4.7 кОм | Ограничивает ток через внутренние защитные диоды A0 (допустимо ≤ 10 мА), если на сигнальный провод попадёт +12 В (ошибка в разъёме, повреждение кабеля) | (12 − 5.3) В / 4.7 кОм ≈ 1.4 мА; мощность на R1 ≈ 10 мВт |
| C8 100 нФ | Вместе с R1 — RC-фильтр нижних частот: подавляет помехи с длинного кабеля (мотор крана, сеть, Wi-Fi) и отдаёт заряд на коммутируемый вход ADS1115 при каждом преобразовании. Ставится у вывода A0, земля — к GND модуля ADS1115 | fc = 1 / (2π · 4.7 кОм · 100 нФ) ≈ 340 Гц; установление 5τ ≈ 2.4 мс < 8 мс (одно преобразование при 128 SPS) |
| R2 100 кОм | Подтяжка к GND со стороны разъёма: при отключённом датчике вход не «плавает», а показывает 0 В | нагрузка на выход датчика 100 кОм — пренебрежимо мала |

- Ошибка измерения от R1: входное сопротивление ADS1115 на диапазоне ±6.144 В ~10 МОм → ≈ 0.05 %, меньше погрешности датчика.
- При перевёрнутом 3-контактном разъёме +12 В остаётся на среднем контакте и на A0 не попадает.
- Опционально: сдвоенный диод Шоттки BAT54S в узел A0 (на +5V и GND) — внешняя фиксация перенапряжения вместо внутренних диодов ADS1115. Стабилитрон 5.1 В не рекомендуется: его ток утечки около 5 В занижает показания у верхней границы шкалы (10 бар).
- Обрыв датчика по-прежнему не отличим от 0 бар (выход 0–5 В); R2 только устраняет «плавающий» вход.

### 4.3.2 Входная цепь датчика расхода (J3, R13, C12, U2 канал 1)

```
J3.3 ──[R13 1k]──┬── U2 HV1 ══ LV1 ──► IO23
                 │
              C12 10n
                 │
J3.1 ────────────┴── GND        J3.2 ── +5V (питание YF-B10)
```

| Цепь (нетлист) | Узлы |
|---|---|
| Net-(J3-Pin_3) | J3.3, R13.1 |
| /Water_Flow | R13.2, C12.2, U2 HV1 |
| Net-(U1-IO23) | U2 LV1, U1 IO23 |
| +5V | J3.2 |
| GND | J3.1, C12.1 |

| Элемент | Назначение |
|---|---|
| +5V на J3.2 | Питание датчика Холла YF-B10 (3.5–24 В). +3V3 не подходит (ниже минимума 3.5 В); +12V возможен, но выход датчика тогда доходит до 12 В — без пользы и с большим риском |
| U2, канал 1 | Приводит сигнал 0/5 В к 0/3.3 В для IO23 (GPIO ESP32 не выдерживают 5 В). Подтяжки 10 кОм модуля к 5 В (HV) и к 3.3 В (LV) обеспечивают работу и с выходом «открытый коллектор», и с выходом, который сам выдаёт 0/5 В. Сигнал не инвертируется |
| R13 1 кОм | Вместе с C12 — фильтр помех с кабеля; ограничивает ток при статическом разряде |
| C12 10 нФ | Фильтр сигнала на стороне HV |

| Параметр | Значение |
|---|---|
| Частота сигнала | 476 имп/л: ≈ 16 Гц при 2 л/мин, ≈ 400 Гц при 50 л/мин (полупериод 1.25 мс) |
| Фронт вниз (через R13) | τ = 1 кОм · 10 нФ ≈ 10 мкс |
| Фронт вверх (через подтяжку 10 кОм модуля U2) | τ ≈ 100 мкс — в 12 раз меньше полупериода на 400 Гц |
| Уровень 0 при выходе «открытый коллектор» | 5 В · 1 кОм / (10 кОм + 1 кОм) ≈ 0.45 В — ниже порога 0 у ESP32 (0.83 В) |
| Ток датчика | ≤ ~15 мА от +5V |

- Прошивка: `WATER_FLOW_GPIO 23`, `INPUT_PULLUP` (не мешает — подтяжка к 3.3 В уже есть на модуле), прерывание по `FALLING` — подходят.
- Почему IO23, а не IO17: GPIO17 по умолчанию — TX у UART2 (подписан TX2 на DevKit) и оставлен под Serial2 для второго ESP; кроме того, на модуле ESP32-WROVER (с PSRAM) GPIO16/17 заняты памятью, а IO23 свободен. IO23 — не strapping-вывод, без подтяжек при сбросе, поддерживает прерывание.
- Тип выхода конкретного экземпляра можно проверить: питание 5 В, сигнал ни к чему не подключён, прокрутить крыльчатку. Меняется 0/5 В — выход сам выдаёт уровень; «плавает» или около 0 — открытый коллектор. Схема работает в обоих случаях.
- J2 и J3 — одинаковые разъёмы JST XH 3P с одинаковым порядком контактов, но на среднем контакте разное питание: 12 В и 5 В. Перепутывание неопасно (YF-B10 выдерживает 12 В, ток в A0 ограничит R1; SWP-300 при 5 В просто не будет работать), но разъёмы стоит подписать на шелкографии: «PRESS 12V» / «FLOW 5V».

### 4.4 Логика управления краном (DRV8871)

Входы IN1/IN2 управляются от IO19/IO18 без преобразователя уровней, через диоды Шоттки D3/D4: порог VIH у DRV8871 ≈ 1.5 В, уровня ≈ 3.1 В (3.3 В минус падение на диоде) достаточно. Параллельно МК входами управляют кнопки SW1/SW2 (см. 4.4.1).

| IN1 (IO19 или SW1) | IN2 (IO18 или SW2) | Выход | Действие |
|---|---|---|---|
| 0 | 0 | Z (coast), через ~1 мс — сон | стоп |
| 1 | 0 | OUT1 = +12V, OUT2 = GND | открытие |
| 0 | 1 | OUT1 = GND, OUT2 = +12V | закрытие |
| 1 | 1 | оба на GND (brake) | стоп (торможение) |

Во время сброса/загрузки ESP32 выводы IO18/IO19 находятся в высокоимпедансном состоянии (это не strapping-выводы), внешние подтяжки R4 (IN1) и R3 (IN2) по 47 кОм к GND, параллельно внутренним подтяжкам DRV8871, выставляют оба входа в 0 (D3/D4 при этом закрыты) → режим coast, затем сон → **кран при перезагрузке не двигается**. Это корректное безопасное поведение.

R3/R4 задают уровень 0 и тогда, когда плата ESP32 не установлена, и не зависят от наличия внутренних подтяжек в конкретном модуле DRV8871; кроме того, они повышают помехоустойчивость входов. Нагрузка на GPIO в состоянии 1: 3.3 В / 47 кОм ≈ 70 мкА на каждый вывод (вместе с внутренней подтяжкой DRV8871 — порядка 0.1 мА), что пренебрежимо мало.

### 4.4.1 Ручное управление краном (SW1, SW2, D3, D4, R3–R8, C9–C11)

Реализует требование `INFO.txt` «Ability to open/close Electrical Water Valve without MC (phisical buttons)»: выносные кнопки без фиксации подают 1 прямо на входы DRV8871, минуя ESP32. Ручное управление работает, даже если ESP32 завис, не загружен или плата DevKit не установлена: питание кнопок берётся от +5V (LM2596), а не от LDO DevKit.

```
                      +5V
                       │
                   [R5 7.5k]
                       │  ≈ 3.33 В
              ┌────────┼────────┬───────────────┐
              │        │        │               │
          [R6 15k]  C9 100n   [SW1 Open]     [SW2 Close]
              │        │        │               │
             GND      GND       │               │
                                │               │
IO19 ──►|── D3 ─────────────────┼──► IN1 (U3)   │
                                │               │
                 IO34 ◄─[R7 10k]┤               │
                        R4 47k ─┤               │
                       C10 100n ┘ → GND         │
                                                │
IO18 ──►|── D4 ─────────────────────────────────┼──► IN2 (U3)
                                                │
                                 IO35 ◄─[R8 10k]┤
                                        R3 47k ─┤
                                       C11 100n ┘ → GND
```

| Цепь (нетлист) | Узлы |
|---|---|
| /valve_open | U1 IO19, D3 A |
| Net-(D3-K) — IN1 | D3 K, R4, C10, R7.2, SW1.1, U3 IN1 |
| /valve_close | U1 IO18, D4 A |
| Net-(D4-K) — IN2 | D4 K, R3, C11, R8.1, SW2.1, U3 IN2 |
| Net-(C9-Pad1) — питание кнопок | R5.2, R6.1, C9, SW1.2, SW2.2 |
| /IO34 | U1 IO34, R7.1 |
| /IO35 | U1 IO35, R8.2 |
| +5V | R5.1 |
| GND | R3.2, R4.2, R6.2, C9, C10, C11 |

**Назначение элементов**

| Элемент | Назначение |
|---|---|
| D3, D4 (1N5817) | GPIO может только подать 1 на IN, но не притянуть его к 0. Если кнопка нажата при GPIO = 0, диод закрыт и кнопка не замыкается на выход GPIO. Заодно диод не пропускает на GPIO напряжение выше 3.3 В. Диод со стороны кнопки не нужен: кнопка либо разомкнута, либо подаёт то же питание кнопок |
| R3, R4 (47 кОм) | Подтяжка IN2/IN1 к 0, когда GPIO = 0 (через закрытый диод GPIO вход к 0 не притянет), при загрузке ESP32 и при отпущенной кнопке |
| R5, R6 (7.5 / 15 кОм) | Делитель от +5V: питание кнопок ≈ 3.33 В, независимо от LDO DevKit. R6 = 15 кОм выбран так, чтобы при нажатии уровень на IN был с запасом выше порога 1 у ESP32 (чтение через IO34/IO35). R5 ограничивает ток, если провод кнопки замкнёт на GND |
| C9 (100 нФ) | Фильтр узла питания кнопок; при нажатии отдаёт заряд в C10/C11 |
| C10, C11 (100 нФ) | Фильтр входов IN1/IN2 от наводок и статики с проводов выносных кнопок, подавление дребезга контактов |
| R7, R8 (10 кОм) | Подключают узлы IN1/IN2 к входам IO34/IO35 для чтения состояния. Ограничивают ток в защитные диоды ESP32 при статике с проводов кнопок. На уровень узла не влияют (вход GPIO высокоомный). Подтяжки для IO34/IO35 не нужны — их роль выполняют R4/R3 |
| SW1, SW2 | Кнопки без фиксации, разъёмы JST XH 2P: pin 1 — IN, pin 2 — питание кнопок. Тумблер с фиксацией не годится: в положении OPEN вход IN1 постоянно в 1, и при протечке команда МК на закрытие даст только brake — кран не закроется |

**Уровни** (порог DRV8871: VIH ≈ 1.5 В, VIL ≈ 0.5 В; порог ESP32: VIH = 0.75 · 3.3 ≈ 2.48 В, VIL = 0.25 · 3.3 ≈ 0.83 В)

| Режим | IN / IO34 (IO35) | Запас до VIH ESP32 |
|---|---|---|
| Питание кнопок, кнопки отпущены | 5 · 15 / (7.5 + 15) ≈ 3.33 В | — |
| GPIO = 1 (через D3/D4; падение на 1N5817 при ~0.1 мА ≈ 0.15–0.2 В) | ≈ 3.1 В | ≈ 0.6 В |
| Нажата одна кнопка (R6 ∥ R4 ∥ внутренняя подтяжка DRV8871 ~100 кОм ≈ 10.2 кОм) | ≈ 2.9 В (≈ 3.0 В без внутренней подтяжки) | ≈ 0.4 В |
| Нажаты обе кнопки | ≈ 2.5 В на обоих входах → brake, кран стоит | ≈ 0.07 В — на грани, но режим и так нерабочий |
| Всё отпущено, GPIO = 0 | 0 В (R3/R4) | — |

| Параметр | Значение |
|---|---|
| Запас по 1 для DRV8871 | более 1 В во всех режимах |
| Максимум на IO34/IO35 | ≤ 3.3 В |
| Обратное напряжение на D3/D4 (кнопка нажата, GPIO = 0) | ≈ 2.9 В, ток утечки — единицы мкА |
| Ток при замыкании провода кнопки на GND | 5 В / 7.5 кОм ≈ 0.67 мА — питание ESP32 не просядет |
| Постоянный ток делителя | 5 В / 22.5 кОм ≈ 0.22 мА |

**Динамика**

| Событие | Что происходит | Время |
|---|---|---|
| МК даёт 1 | GPIO заряжает C10/C11 через открытый диод | микросекунды |
| МК даёт 0 | Диод закрыт, C10/C11 разряжаются через R4/R3 ∥ внутреннюю подтяжку (≈ 32 кОм), τ ≈ 3.2 мс | ниже VIL ESP32 (0.83 В) через ≈ 4–6 мс; ниже VIL DRV8871 (0.5 В) через ≈ 6–9 мс |
| Нажатие кнопки | C9 делит заряд с C10 — вход сразу ≈ 1.7 В, затем дозаряд через R5, τ ≈ 0.9 мс | до ≈ 2.9 В за ≈ 2–3 мс |
| Отпускание кнопки | Разряд через R4/R3 | ≈ 6–9 мс |
| Узел питания кнопок | R5 ∥ R6 = 5 кОм с C9, τ ≈ 0.5 мс | фильтр помех на проводе |

На входах IN частота среза фильтра около 50 Гц: короткие наводки на кабеле кнопок не доходят до порога 1.5 В.

**Поведение**

- Кран движется, пока кнопка нажата. У CR01 есть встроенные концевики: кнопку можно держать до конца хода, в крайнем положении кран обесточится сам.
- Нажатие кнопки во время встречного хода по команде МК → brake на ~30 мс (антидребезг), затем прошивка снимает свой выход, и кран идёт по кнопке. Команды при нажатой кнопке игнорируются. Обе кнопки сразу → brake, кран стоит. Это безопасно.
- Задержка остановки 6–9 мс из-за C10/C11 ни на что не влияет: CR01 останавливается концевиками, прошивка — по таймеру 7 с.
- При реверсе прошивка снимает выход и включает противоположный через 20 мс (`VALVE_REVERSE_PAUSE_MS`, без блокировки `loop()`): за это время C10/C11 разряжаются, поэтому brake на 1–9 мс, когда оба входа в 1, не возникает.

**Чтение состояния прошивкой (IO34/IO35)**

| IO34 (IN1) | IO19 (свой выход) | Значит |
|---|---|---|
| 0 | 0 | кнопка Open не нажата |
| 1 | 0 | нажата кнопка Open |
| 1 | 1 | кран открывает МК |
| 0 | 1 | ошибка: выход в 1, а на узле 0 (обрыв D3, КЗ узла IN1 на GND) |

Для IO35 / IO18 (Close) — аналогично. Требования к прошивке:

- **Маскирование после выключения выхода.** Когда МК переводит IO19/IO18 в 0, C10/C11 разряжаются, и ≈ 4–6 мс вход остаётся в 1. Чтобы хвост собственной команды не был принят за нажатие, после выключения выхода вход нужно игнорировать ~20 мс.
- **Антидребезг:** 20–50 мс программно (C10/C11 уже сглаживают основной дребезг).
- GPIO34/35 — только входы, без внутренних подтяжек: `pinMode(VALVE_OPEN_STATUS, INPUT)`, `pinMode(VALVE_CLOSE_STATUS, INPUT)` (макросы в `Application.h`).
- Чтение пока не реализовано (см. 7.2, п. 14).

**Размещение на плате:** C10/C11 — рядом с разъёмами SW1/SW2, куда приходит провод кнопки, чтобы статический разряд уходил в конденсатор раньше, чем дойдёт до DRV8871; C9 — рядом с R5/R6; R7/R8 — ближе к выводам IO34/IO35. Порядок контактов SW1/SW2 (pin 1 — IN, pin 2 — питание кнопок) подписать на шелкографии.

### 4.4.2 Индикация команды на кран (LED5, LED6: D9, D10, R14)

```
OUT1 ──[R14 2.2k]──┬──►|── D9  LED5 (Open, зелёный)  ──┬── OUT2
                   └──|◄── D10 LED6 (Close, красный) ──┘
```

| Цепь (нетлист) | Узлы |
|---|---|
| Net-(J1-Pin_1) — OUT1 | U3 OUT1, J1.1, R14.2 |
| Net-(D10-K) | R14.1, D9 A, D10 K |
| Net-(D10-A) — OUT2 | U3 OUT2, J1.2, D9 K, D10 A |

| Режим DRV8871 | Горит | Ток |
|---|---|---|
| Open: OUT1 = +12V, OUT2 = GND | D9 LED5 (Open) | (12 − 2.0) / 2.2 кОм ≈ 4.5 мА |
| Close: OUT2 = +12V, OUT1 = GND | D10 LED6 (Close) | ≈ 4.5 мА |
| Coast / сон / brake | ничего | 0 |

- Светодиоды стоят на выходе DRV8871, поэтому показывают команду независимо от источника — кнопка SW1/SW2 или МК — и не нагружают логические узлы IN1/IN2. Подключение к узлам IN через 240 Ом (первый вариант) «садило» узел при нажатии кнопки до ≈ 1.8–2.0 В: IO34/IO35 переставали видеть нажатие, а запас DRV8871 падал до 0.3–0.5 В.
- Обратное напряжение на погашенном светодиоде равно падению на горящем (≈ 2 В) — меньше допустимых 5 В.
- Мощность на R14 ≈ 45 мВт; добавка к току DRV8871 несущественна.
- Светодиоды показывают поданное напряжение, а не движение крана: когда встроенный концевик CR01 обесточит мотор, светодиод горит, пока подана команда (до 7 с от прошивки или пока нажата кнопка).

### 4.6 Светодиоды индикации (D5–D8, R9–R12)

```
+3V3 ──[R9 200]──►|── D5 LED1 WiFi  (синий)   ──► IO32
+3V3 ──[R10 240]─►|── D6 LED2 Valve (зелёный) ──► IO33
+3V3 ──[R11 510]─►|── D7 LED3 Flow  (жёлтый)  ──► IO25
+3V3 ──[R12 510]─►|── D8 LED4 Error (красный) ──► IO26
```

Светодиод горит при 0 на выводе (активный LOW) — это совпадает с `LED_PULLUP` в `connectionMonitor`. По сравнению с подключением «GPIO → LED → GND» схема электрически равноценна: у ESP32 ток в 0 (до ~28 мА) и в 1 (до ~40 мА) с большим запасом перекрывает ток светодиода. Плюс — единообразие с библиотекой и другими проектами SmartHome. При загрузке выводы в высокоимпедансном состоянии, светодиоды не горят. GPIO32/33/25/26 — не strapping-выводы.

| LED | Резистор | Падение на LED при 1–5 мА | Ток |
|---|---|---|---|
| D5 WiFi (синий) | 200 Ом | ≈ 2.6–2.8 В | ≈ 2–3 мА |
| D6 Valve (зелёный) | 240 Ом | ≈ 1.9–2.0 В (обычный) / ≈ 2.6–2.7 В (InGaN) | ≈ 5 мА / ≈ 2 мА |
| D7 Flow (жёлтый) | 510 Ом | ≈ 1.9–2.0 В | ≈ 2.5 мА |
| D8 Error (красный) | 510 Ом | ≈ 1.8 В | ≈ 2.7 мА |

Расчёт: I = (3.3 − 0.1 − падение на LED) / R, где 0.1 В — остаточное напряжение на выводе GPIO в 0. Суммарно от +3V3 — не более ~12 мА.

- Резисторы подобраны под цвет: яркость всех четырёх примерно одинакова. Если обычный зелёный окажется ярче остальных, R10 можно увеличить до 510 Ом.
- Яркость синего сильнее всего зависит от экземпляра — проверить на макете; если тусклый, R9 = 100–150 Ом.
- В прошивке: включение — `LOW`; при инициализации сначала `digitalWrite(pin, HIGH)`, затем `pinMode(pin, OUTPUT)`, чтобы светодиод не мигнул при старте.
- LED5/LED6 (Open/Close) — без GPIO, на выходе DRV8871, см. 4.4.2.
- LED7 (Power) из `INFO.txt` на схеме нет: его можно подключить к +5V через резистор без GPIO — индикация питания от LM2596.

## 6. Прошивка

### 6.1 Сборка

```sh
pio run -e RELEASE_OTA_esp32dv                 # сборка
pio run -e RELEASE_OTA_esp32dv -t upload       # прошивка по OTA (хост "watercontroller1")
pio run -e RELEASE_COM_esp32dv -t upload       # прошивка по COM7
pio device monitor -e RELEASE_COM_esp32dv      # монитор, 115200
```

Переменные окружения: `SMARTHOME_WIFI_SSID`, `SMARTHOME_WIFI_PWD`, `SMARTHOME_MQTT_BROKER`, `SMARTHOME_OTA_PASSWD` (и варианты `_OFFICE`).
Библиотеки: ArduinoJson ~6.19.4, PubSubClient ~2.8, Adafruit ADS1X15 ^2.5.0.

### 6.2 Архитектура

- Кооперативный неблокирующий super-loop: `loop()` по очереди вызывает `handleClient()` / `*_handle()` всех модулей; все задержки сделаны на `millis()`.
- `src/lib/` — общая инфраструктура проектов SmartHome: `wifiConnect`, `mqttClient`, `otaClient` (владеет mDNS), `connectionMonitor`, `serialDebug`, `profiler`, `Log`, `TimeUtils`.
- Прикладные модули:

| Модуль | Функция |
|---|---|
| `valve.cpp` | H-мост: открытие/закрытие подачей 1 на IN1/IN2, автостоп через `valve_move_time_mills = 7000` мс |
| `ads.cpp` | ADS1115 (gain 2/3, ±6.144 В, 0.1875 мВ/бит), одиночное преобразование с таймаутом 50 мс; при пропаже устройства повторная инициализация раз в минуту |
| `pressure_sensor.cpp` | канал A0, `бар = В × 2`, ограничение 0–10 бар; отбрасывает значения вне −0.1…5.1 В; публикация каждые 10 с |
| `water_flow.cpp` | прерывание по спаду на GPIO23 (`WATER_FLOW_GPIO`), подсчёт импульсов под `portMUX`; раз в 60 с публикуется расход в л/мин (= импульсы / 476) |
| `debug.cpp` | команды серийной консоли: `wifi_reconnect`, `wifi_set_11b/g/n/lr`, `wifi_info`, `mqtt_info`, `restart` |

- Время: SNTP `pool.ntp.org`, часовой пояс Израиля.

## 7. Результаты анализа

### 7.1 Схема

**Важно**

1. **Нет разъёма ввода питания 12 В.** Цепь +12V помечена только PWR_FLAG. Нужно добавить клеммник/разъём, а также:
   - защиту от переполюсовки (Шоттки последовательно или P-MOSFET);
   - самовосстанавливающийся предохранитель ~0.75–1 А;
   - TVS-диод на +12V (например, SMBJ15A) — линия идёт к крану и датчику по длинным кабелям.
2. ✅ **Датчик расхода YF-B10 — выполнено:** разъём J3 (GND / +5V / сигнал), сигнал через R13 1 кОм и C12 10 нФ, уровень 5 → 3.3 В через канал 1 U2 на IO23 (см. 4.3.2). Остаётся подписать J2/J3 на шелкографии.
3. ✅ **Защита входа A0 ADS1115 — выполнено:** R1 4.7 кОм последовательно + C8 100 нФ на GND (см. 4.3.1). Опционально — BAT54S.
4. **Обрыв датчика давления не отличим от 0 бар.** Выход 0–5 В, 0 бар = 0 В. ✅ Подтяжка R2 100 кОм к GND добавлена — «плавающего» входа нет. Для надёжной диагностики обрыва лучше датчик с выходом 0.5–4.5 В.
5. **Датчик давления питается от 12 В — нижняя граница диапазона 12–36 В.** С учётом допуска БП и падений на кабеле напряжение может опуститься ниже 12 В. Проверить точность при 11.5–12 В; при необходимости — БП 15 В (DRV8871 и LM2596 это допускают) или отдельный повышающий DC-DC.
6. **На схеме отсутствуют** светодиод LED7 (Power), переключатель блокировки, кнопка AP/конфигурации, датчики температуры, датчик протечки, детектор сетевого питания — все они есть в требованиях (`INFO.txt`). ✅ Кнопки открытия/закрытия (SW1/SW2) добавлены — см. 4.4.1. ✅ Светодиоды LED1–LED4 (D5–D8) добавлены — см. 4.6. ✅ LED5/LED6 (Open/Close) на выходе DRV8871 — см. 4.4.2.
7. **У U2, U3, U4 не назначены футпринты** (value `~`, footprint пустой) — нужно исправить до разводки платы.

**Средне / для сведения**

8. ✅ **Level shifter на входах DRV8871 убран — выполнено:** IN1/IN2 управляются от IO19/IO18 через D3/D4 (VIH DRV8871 ≈ 1.5 В). При сбросе — coast (R3/R4 47 кОм + внутренние подтяжки DRV8871 к GND), кран не двигается. Канал 1 U2 использован под сигнал YF-B10, каналы 2–3 — I2C, канал 4 свободен.
9. **D2 1N5817 снижает +5V примерно на 0.3–0.4 В** (1N5817 заменил 1N5819: падение меньше, обратное напряжение 20 В — для шины 5 В достаточно). Выход LM2596 нужно выставить на ~5.3–5.4 В, чтобы на ADS1115 и HV-стороне было ≥ 4.9 В (иначе сигнал 5 В от датчика превысит VDD ADS1115).
10. **C3 470 мкФ на +3V3** — большая ёмкость на выходе LDO DevKit (увеличивает пусковой ток). Обычно хватает 22–100 мкФ. Не критично.
11. **Нет обратной связи о положении крана.** У CR01 есть встроенные концевики, но это 2-проводная модель без выводов состояния; прошивка «считает» кран открытым/закрытым по последней команде; ручные нажатия SW1/SW2 прошивка читает через IO34/IO35. Варианты: кран с выводами состояния концевиков (модели CR04/CR05) или измерение тока хода через шунт.
12. **При пропадании питания кран остаётся в последнем положении** (вода не перекрывается). Для защиты от протечек при отключении сети — UPS/аккумулятор на 12 В и вход «AC power detect» (уже есть в требованиях).
13. ✅ **Чтение нажатий SW1/SW2 — выполнено в схеме:** узлы IN1/IN2 заведены на входы IO34/IO35 через R7/R8 10 кОм; R6 увеличен до 15 кОм для запаса по уровню (см. 4.4.1). Поддержка в прошивке есть (7.2, п. 14).
14. ✅ **Разъёмы SW1/SW2 — выполнено:** JST XH 2P вертикальные. Порядок контактов (pin 1 — IN, pin 2 — питание кнопок) подписать на шелкографии.
15. **Переключатель блокировки открытия** не реализован. Последовательно с SW1 он заблокирует только ручное открытие; чтобы блокировалась и команда МК, он должен разрывать и цепь D3 (например, IN1 целиком), или МК должен читать его состояние.

### 7.2 Прошивка

1. ✅ `VALVE_LED` исправлен на 33 — совпадает со схемой (D6). `FLOW_LED`, `ERROR_LED`, `VALVE_LED` объявлены, но в коде пока не используются; используется только `TEST_WIFI_LED` в `connectionMonitor`.
2. ✅ Подключение LED согласовано: на схеме анод через резистор к +3V3, катод на GPIO (активный LOW) — как `LED_PULLUP` в прошивке. Устарел только `INFO.txt` («pull-down»). При инициализации LED: сначала `HIGH`, потом `OUTPUT`.
3. `AC_POWER_DETECT_GPIO ?` — заглушка, при первом использовании сломает сборку.
4. Подписка на `valve_enable/get` есть, а в `mqtt_callback()` его нет. ✅ `flowrate/get` обрабатывается через `water_flow_get()`.
5. `valve/open` и `valve/close` игнорируют payload. Если в брокере окажется retained-сообщение на `valve/open`, кран будет открываться при каждом переподключении. Рекомендуется проверять payload и игнорировать retained-сообщения для команд.
6. ✅ Состояние крана публикуется в `valve/state` (вычисляется по командам и удержанию кнопок, датчика положения нет). После загрузки и после неполного хода — `unknown` до завершения полного хода.
7. **Основная функция — обнаружение протечки и автоматическое закрытие — пока не реализована.** Возможные правила: непрерывный расход дольше N минут, расход выше порога, падение давления при закрытом кране, сигнал датчика протечки.
8. ✅ Накопительный счётчик объёма публикуется в `flowtotal` — для Home Assistant (Utility Meter / панель Energy → Water, `state_class: total_increasing`). Обрыв MQTT его не сбрасывает, но счёт хранится в RAM: после перезагрузки начинается с 0, вода за время перезагрузки не учитывается.
9. `ads_voltage_chnnel_get()` ждёт окончания преобразования в цикле с `delay(1)` до 50 мс (обычно ~8 мс) — небольшое нарушение неблокирующего принципа.
10. Давление публикуется каждые 10 с (`pressure_sensor_init(10000L)`), а в требованиях — 15 с / 1 мин.
11. `board = wemos_d1_mini32`, а железо — ESP32-DevKitC-32U. Работает (тот же чип), но лучше `esp32dev`, чтобы соответствовать схеме.
12. `valve_move_time_mills = 7000` нужно сверить с реальным временем хода CWX-25S (у разных версий 3–15 с). У CR01 есть встроенные концевики, поэтому время можно взять с запасом.
13. ✅ Реверс крана с паузой 20 мс (`VALVE_REVERSE_PAUSE_MS`, см. 4.4.1): без блокировки `loop()`, через `valve_handle()`.
14. ✅ Чтение кнопок через IO34/IO35 реализовано в `valve.cpp`: `INPUT` без подтяжек, нажатие распознаётся при своём выходе = 0, маскирование 20 мс после выключения выхода, антидребезг 30 мс, публикация в `valve/state` и `valve/manual`. Кнопка приоритетнее прошивки: нажатие отменяет ход по команде, а команды при нажатой кнопке игнорируются. Удержание короче 7 с даёт `unknown`, если кран не был уже в этом положении.
15. ✅ Комментарий в `Application.h` исправлен на `// ESP32: ESP-32U-38PINs:`; для ESP8266 добавлен `#error ESP8266 Not supported`. `WATER_FLOW_GPIO` = 23 — совпадает со схемой.

## 9. Рекомендации по свободным GPIO (ESP32-WROOM-32U)

Избегать strapping-выводов 0, 2, 5, 12, 15 (IO12 нельзя подтягивать к 1 при загрузке) и выводов flash 6–11 (SD0–SD3, CMD, CLK). Уже заняты: 23 (датчик расхода), 16, 17 (резерв Serial2 для второго ESP), 18, 19 (кран), 21, 22 (I2C), 34, 35 (чтение состояния кнопок Open/Close), 25, 26, 32, 33 (светодиоды LED1–LED4).

| Функция | Предлагаемый GPIO | Примечание |
|---|---|---|
| 1-Wire (DS18B20: труба + воздух на одной шине) | 4 | подтяжка 4.7 кОм к +3V3 |
| Кнопка AP/конфигурации / KEY1 | 39 (VN) | только вход, **нет внутренних подтяжек** — внешние 10 кОм к +3V3 + RC-фильтр |
| Датчик протечки | 36 (VP) | то же; или резистивный датчик через A1 ADS1115 |
| AC power detect | 27 | через делитель/оптопару от входа сетевого БП |
| Переключатель блокировки открытия (если его читает МК) | 13 или 14 | внутренняя подтяжка или внешние 10 кОм |
| Второй ESP (Serial2) | RX 16, TX 17 | «родные» выводы UART2: `Serial2.begin(baud)` без переназначения. При переходе на ESP32-WROVER (PSRAM на GPIO16/17) UART2 придётся перенести, например на 13/14 |
| Резерв (полив и др.) | 13, 14 | 13/14 — если не заняты переключателем блокировки |

**Кнопки Open/Close** реализованы аппаратно и своих выходов GPIO не занимают; их состояние читается через IO34/IO35 (R7/R8 10 кОм, см. 4.4.1).

Вопрос из `INFO.txt` «можно ли использовать input-only GPIO для кнопок»: да, GPIO34–39 подходят для кнопок и для чтения состояний, но только с внешними подтягивающими резисторами (у этих выводов внутренних подтяжек нет). GPIO34/35 уже использованы для кнопок крана (подтяжки — R4/R3), свободными остаются GPIO36 и GPIO39.
