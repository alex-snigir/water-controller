H/W devices:
============

  Valve electrical:
  =================
    CR01, 12V, DN20(3/4) Model: CWX-25S
    CR01 - не потребляет ток ни в открытом не в закрытом положении. Управляется 2мя проводами сменой полярности.
	CR01 имеет концевики
    Power supply: 12V
	Power: <2W
	Full opening/closing time: 5 sec (полный ход)
    Working current: <80mA
  
  Water Flow Sensor:
  ==================
    YF-B10 1" 2-50L DC3.5~24V 476 pulse/L
    Power supply: 3.5V–24V; Note: 5V used for actual connection
  
  Pressure Sensor electrical:
  ===========================
    Model: SWP-300  0-5V G1-2, 0-10bar
    Connection: 1/2" Father
    Power supply: 12V-36VDC (default 24VDC); Note: 12V used for actual connection
    Signal: 0-5V
  
  Pressure Sensor mechanical:
  ===========================
    Connection: 1/4" Father
  
Power Consumption:
==================
    8 mA / 12V   - DC-DC 12V->5V Idle mode (LED)
   70 mA /  5V   - MC, Controller electronics
    3 mA / 12V   - Valve control: DRV8871 H-Bridge
   80 mA / 12V   - Electrical Valve CR01
   50 mA / 12V   - Pressure Sensor electrical
   12 mA / 3V3   - 4 LEDs D5–D8
  4.5 мА / 12V   - LED5/LED6 только во время команды на кран
   15 mA /  5V   - YF-B10 Water Flow
   ?? mA /  ?V   - Система полива, Netafim Valves
   ~3 mA / 3V3   - 2x DS18B20 и SHT41
		  
  Valve control: Relay version: (not used)
  18 mA / 12V - Direction Relay, after DC-DC 12V->5V - 30mA/5V
  25 mA / 12V - Power Relay, after DC-DC 12V->5V - 50mA/5V


MC:
===
  ESP32-WROOM-32U with external antenna
  Power: 5V (5V is used to reuse the same voltage as for the ADS1115 and Level Shifter)


  GPIO:
  =====
  GPIO 21+ (SDA)  - LogicLevel LV3 -> HV3 -> SDA ADS1115 (A0 Pressure Sensor);   SDA SHT41 (Box Temperature/Humidity sensor)
  GPIO 22+ (SCL)  - LogicLevel LV2 -> HV2 -> SCL ADS1115                     ;   SCL SHT41 (Box Temperature/Humidity sensor)
  GPIO 32+        - LED: LED1 WiFi/MQTT Status (Blue) (pull-up)
  GPIO 23+        - Water Flow: LogicLevel LV1 -> HV1 -> J3 (interrupt attached)
  GPIO ??         - AC Power detected (in case of UPS used) (pull-up)             <<- What is it??

  Valve control: DRV8871 H-Bridge:
  GPIO 19+        - Valve open (pull-down)              Open: HIGH  Close: LOW   Stop: LOW  Brake: HIGH
  GPIO 18+        - Valve close (pull-down)                   LOW          HIGH        LOW         HIGH
  
  DPDT+SPDT Relay version
  GPIO 19+        - Valve direction (pull-down)              HIGH: Open      LOW: Close
  GPIO 18+        - Valve power on (pull-down)               HIGH: Power-ON  LOW: Power-OFF

  GPIO 05+        - Water Pipe temperature (DS18B20): J4 (DQ/GND/3V3), pull-up R15 4.7K
  GPIO 15+        - Air temperature (DS18B20):        J5 (DQ/GND/3V3), pull-up R16 4.7K
  GPIO ??         - Сенсор протечки
  GPIO 34+        - Physical button/IN1 (open valve) status              <<- Pure INPUT GPIO can be used
  GPIO 35+        - Physical button/IN2 (close valve) status             <<- Pure INPUT GPIO can be used
  GPIO 13+        - Lock Switch J7 (input, 1 = locked, R18 pull-up): jumpers 1-2 and 3-4 (or DPST switch "Normal") - open allowed; no jumpers / "LOCK" / cable pulled out - opening blocked in hardware (IN1 cut), closing works
  GPIO ??         - Spare KEY1 Button                                    <<- подойдут GPIO36/39 с внешней подтяжкой
  GPIO 33+        - LED: LED2 Water Valve Status (Green) (pull-up)
  GPIO 25+        - LED: LED3 Water Flow Rate (Yellow) (pull-up)
  GPIO 26+        - LED: LED4 Error (Red)  (pull-up)
  GPIO 16         - reserved for Serial2 RX to connect 2nd ESP
  GPIO 17         - reserved for Serial2 TX to connect 2nd ESP

I2C Addresses:
==============
  0x48 - ADS1115
  0x44 - SHT41-AD1B
  0x45 - SHT41-BD1B
  0x70 - SHTC3 для испытаний

	> Физический переключатель блокирования открытия крана

  =====================

    > Realtime Water Pressure Sensor read
  Temperatures:
  =============
    > Read Water Pipe temperature DS18B20
    > Read Air temperature DS18B20
	> Box Temperature/Humidity SHT41
    > ESP chip internal Temperature (ESP32 internal)
  Notifications:
  ==============
    - MQTT connected
	- Water Flow Rate
	- Water Pressure Rate
	- Протечка
	- Temperature
  > Кнопка включения AP/конфигурации
  
  > LED: WiFi/MQTT Status   LED1 (Blue)    - WiFi/MQTT status OFF: WiFi is not connected, Blinking: WiFi connected but MQTT is not connected, ON: WiFi+MQTT connected 
  > LED: Water Valve Status LED2 (Green)   - ON:valve open, OFF: valve closed, Blinking: valve opening/closing, Short flash every 2 s: valve state unknown
  > LED: Water Flow Rate    LED3 (Yellow)  - blinking according to flow rate
  > LED: Error              LED4 (Red)     - ON: an alarm is active (freeze, overheat, condensation, low_pressure), Slow blink (1 s): a temperature/box sensor is "error" or "no_sensor", Double short flash every 2 s: opening is blocked (lock switch or valve_enable = 0), 3 fast blinks: an open was rejected by the lock switch ("locked"), 2 long blinks: an open was rejected by valve_enable = 0 ("disabled"), OFF: none of these
  > LED: Valve Opening      LED5 (Green)   - Valve Opening Status
  > LED: Valve Closing      LED6 (Red)     - Valve Closing Status
  > LED: Power              LED7 (Green)   - Power is ON. GPIO not used. LED not yet implemented. Reserved

MQTT Interface:
=============== 
  Announcement: "home/announcement/watercontroller1"   // Payload: "connected"    - Sent by device when connected to broker, just before topics subscription
  Clear retained: "valve/open", "valve/close", "valve_enable/set" // Payload: ""  - Sent RETAIN=true by device on connect, after the announcement and before subscribing: deletes a command retained by mistake, so it is not run again on every reconnect/reboot
  LastWill:     "home/announcement/watercontroller1"   // Payload: "disconnected" - Sent by broker when client disconnected from MQTT broker
  
  Subscribed:
  ===========
    "home/alive/get"                        // RETAIN=false  Payload: N/A    - Get device info: request the "home/alive" response
    "home/watercontroller1/info/get"        // RETAIN=false  Payload: N/A    - Get device info: request the "home/watercontroller1/info" response 
    "home/watercontroller1/valve/open"      // RETAIN=false  Payload: N/A    - Open water valve. Must not be retained: a retained one is deleted by the device on connect
    "home/watercontroller1/valve/close"     // RETAIN=false  Payload: N/A    - Close water valve. Must not be retained: a retained one is deleted by the device on connect
    "home/watercontroller1/valve/state/get" // RETAIN=false  Payload: N/A    - Get valve state: request the "home/watercontroller1/valve/state" response
    "home/watercontroller1/valve/lock/get"  // RETAIN=false  Payload: N/A    - Get lock switch state: request the "home/watercontroller1/valve/lock" response
    "home/watercontroller1/valve_enable/get" // RETAIN=false Payload: N/A    - Get software open permission: request the "home/watercontroller1/valve_enable" response
    "home/watercontroller1/valve_enable/set" // RETAIN=false Payload: STRING - "1": allow opening, "0": forbid opening by MQTT commands (SW1 button still opens, closing always works). Kept in NVS, written only on change, default "1". Any other payload, empty included, is ignored (logged). Must not be retained: a retained one is deleted by the device on connect
    "home/watercontroller1/pressure/get"    // RETAIN=false  Payload: N/A    - Get pressure: request the "home/watercontroller1/pressure" response with the last reading
    "home/watercontroller1/flowrate/get"    // RETAIN=false  Payload: N/A    - Get flow rate: request the "home/watercontroller1/flowrate" response with the last calculated value
    "home/watercontroller1/temperature/get" // RETAIN=false  Payload: N/A    - Get temperatures: request "home/watercontroller1/temperature/pipe" and ".../temperature/air" with the last readings, or their status if there is no valid reading
    "home/watercontroller1/box/get"         // RETAIN=false  Payload: N/A    - Get box air: request "home/watercontroller1/box/temperature", ".../box/humidity" and ".../box/dewpoint" with the last reading, or "box/status" if there is no valid reading
    "home/watercontroller1/alarm/get"       // RETAIN=false  Payload: N/A    - Get alarms: request "home/watercontroller1/alarm/freeze", ".../alarm/overheat", ".../alarm/condensation" and ".../alarm/low_pressure"
  
  Published:
  ==========
    "home/alive"                            // RETAIN=false  Payload: JSON   - Sent in response of "home/alive/get"
    "home/keepalive/watercontroller1"       // RETAIN=false  Payload: STRING - Sent each minute. Payload: "connected"
    "home/watercontroller1/info"            // RETAIN=false  Payload: JSON   - Sent in response of "home/watercontroller1/info/get"
    "home/watercontroller1/connection/info" // RETAIN=false  Payload: JSON   - Sent when MQTT connected or re-connected
    "home/watercontroller1/valve/state"     // RETAIN=true   Payload: STRING - Sent on each state change, on MQTT connect and on request. Payload: "unknown", "opening", "open", "closing", "closed"
    "home/watercontroller1/valve/manual"    // RETAIN=false  Payload: STRING - Sent when a physical button is pressed or released. Payload: "open", "close", "released"
    "home/watercontroller1/valve/lock"      // RETAIN=true   Payload: STRING - Lock Switch J7 (GPIO13). Sent on change (50 ms debounce), on MQTT connect and on request. Payload: "locked", "unlocked"
    "home/watercontroller1/valve_enable"    // RETAIN=true   Payload: STRING - Software open permission. Sent on change, on "valve_enable/set", on MQTT connect and on request. Payload: "1", "0"
    "home/watercontroller1/valve/rejected"  // RETAIN=false  Payload: STRING - Open refused: "valve/open" with the lock on ("locked") or with valve_enable = 0 ("disabled"); Open button SW1 pressed with the lock on ("locked"). The valve does not move, "valve/state" is not changed
    "home/watercontroller1/flowrate"        // RETAIN=false  Payload: STRING - Sent each minute and on request. Liters per minute. Payload: "%f"
    "home/watercontroller1/pressure"        // RETAIN=false  Payload: STRING - Sent every 10 seconds and on request. Bar. Payload: "%.2f"
    "home/watercontroller1/flowtotal"       // RETAIN=false  Payload: STRING - Sent each minute. Liters since boot, drops to 0 after reboot. Payload: "%.3f"
    "home/watercontroller1/pressure/status" // RETAIN=true   Payload: STRING - Sent on change, on MQTT connect and in response of "home/watercontroller1/pressure/get" if there is no valid reading. Payload: "unknown", "ok", "over_range" (at or above 10 bar, published value is 10), "no_adc" (ADC lost, after 3 failed readings in a row), "out_of_range"
    "home/watercontroller1/temperature/pipe"        // RETAIN=false  Payload: STRING - DS18B20 on GPIO5 (J4). Sent each minute and on request. Celsius. Payload: "%.2f"
    "home/watercontroller1/temperature/air"         // RETAIN=false  Payload: STRING - DS18B20 on GPIO15 (J5). Sent each minute and on request. Celsius. Payload: "%.2f"
    "home/watercontroller1/temperature/pipe/status" // RETAIN=true   Payload: STRING - Sent on change, on MQTT connect and in response of "home/watercontroller1/temperature/get" if there is no valid reading. Payload: "unknown", "ok", "no_sensor" (no DS18B20 found on the bus), "error" (3 failed readings in a row: disconnected, CRC error or 85 C power-on value)
    "home/watercontroller1/temperature/air/status"  // RETAIN=true   Payload: STRING - Same as "temperature/pipe/status", for the air probe
    "home/watercontroller1/box/temperature" // RETAIN=false  Payload: STRING - SHT41 in the controller box. Sent each minute and on request. Celsius. Payload: "%.2f"
    "home/watercontroller1/box/humidity"    // RETAIN=false  Payload: STRING - Sent each minute and on request. %RH. Payload: "%.1f"
    "home/watercontroller1/box/dewpoint"    // RETAIN=false  Payload: STRING - Sent each minute and on request. Celsius, Magnus formula. Payload: "%.2f"
    "home/watercontroller1/box/status"      // RETAIN=true   Payload: STRING - Sent on change, on MQTT connect and in response of "home/watercontroller1/box/get" if there is no valid reading. Payload: "unknown", "ok", "no_sensor" (no answer at the I2C address, 3 times in a row), "error" (3 failed readings in a row: CRC or bus error)
    "home/watercontroller1/alarm/freeze"       // RETAIN=true  Payload: STRING - Pipe freeze risk: "on" below 3 C, "off" above 4 C (temperature/pipe). Sent on change, on MQTT connect and on request. Payload: "on", "off", "unknown" (no valid reading of a sensor it needs)
    "home/watercontroller1/alarm/overheat"     // RETAIN=true  Payload: STRING - Controller box overheat: "on" above 55 C, "off" below 50 C (box/temperature). Same rules as "alarm/freeze"
    "home/watercontroller1/alarm/condensation" // RETAIN=true  Payload: STRING - Condensation risk: "on" when temperature/air minus box/dewpoint is below 2 C, "off" above 3 C. Same rules as "alarm/freeze"
    "home/watercontroller1/alarm/low_pressure" // RETAIN=true  Payload: STRING - "on" when valve/state has been "open" for 30 s and the pressure stays below 0.5 bar for 30 s, "off" above 1 bar or when the valve is not open. Causes: broken sensor wire (reads 0 bar), no sensor power, no mains water, burst pipe. "unknown" while pressure/status has no valid reading
